- 검사일: 2026-11-22 (한국 시간)
- 대상: React 버전 PostgreSQL 학습 자료 총 97개 중 최신 25개
- 최신 기준: 현재 목록과 동일한 `date DESC NULLS LAST, id ASC`. 등록 시각은 DB에 별도 저장되지 않아 실제 등록 순서를 확정할 수 없다.
- 범위: `bound.json`부터 `adapt.json`까지의 25개를 전체 97개와 비교했다.
- 비교 기준: 파일명과 무관하게 메인 title이 같고, ordinal 순서의 conversations title 배열(개수·순서·값)이 모두 같은 다른 자료가 존재하는지 검사했다.
- 결과: 중복 0개, 삭제 0개. 기존 학습 자료와 진도, 학습 횟수 및 PostgreSQL 영속 볼륨은 보존했다.
- 등록 로직 적용 후 다시 검사한 결과도 전체 97개, 검사 25개, 중복 0개였다.

이 기록은 검사 당시의 결과이며 이후 자료 등록에 따라 달라질 수 있다. `htmlVersion/`의 JSON 파일은 이번 DB 정리 대상이 아니다.

## 사용자 지정 중복 18개 정리

최신 25개 범위 밖에 있는 사용자 지정 자료를 추가 검사했다. `word1.json`부터 `word18.json`까지 18개 모두 같은 메인 제목과 동일한 순서의 대화 제목 목록을 가진 별도 파일명 자료가 존재했다.

- 삭제: DB의 `word1.json`~`word18.json` 18개 및 해당 자료의 연결 기록
- 보존: 이름을 바꾼 대응 자료 18개와 그 학습 기록
- 전체 자료 수: 97개 → 79개
- 삭제 전 학습 데이터 복구용 덤프는 저장소 밖 `/tmp/wordstudy-before-word-cleanup-20261122.sql`에 저장했다. DB 데이터는 커밋하지 않았다.
- 서버 재시작 후 삭제 ID 0개, 대응 자료 18개, 전체 79개 및 health HTTP 200을 확인했다. 기존 seed는 제목 중복 검사로 건너뛰어 재등록되지 않았다.

## 보존 자료 학습 횟수 조정

사용자 요청에 따라 위 정리에서 보존한 대응 자료 18개(`prioritize.json` 포함)의 `study_count`를 각각 1로 설정했다. 지정 ID만 대상으로 트랜잭션을 적용했으며, 완료 후 대상 18개 모두 `study_count = 1`임을 DB에서 확인했다.
